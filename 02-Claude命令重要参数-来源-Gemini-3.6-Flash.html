Learning map 02 · Claude CLI parameter contracts

Claude 命令参数不是语法清单，而是 AI 智能体的运行契约

配置一个 CLI 参数，本质上是在向 autonomous agent 签发一份工作合同：决定它的思考深度、记忆范围、工具权限、算力预算与机器交互协议。

核心判断 传统的命令行 flag 配置格式与选项；AI 时代的命令参数锁死智能体在系统中的授权红线与输出契约。

01

本质：控制 Autonomous Agent 运行状态的结构化声明

`claude` CLI 的参数选项不是为了传参给传统程序，而是为具身在终端中的 AI 智能体设定认知策略、能力沙箱与机器交付接口。

它本质上是人类向 AI 智能体签发的 Agent 运行契约（Agent Operating Contract）。

为什么存在？

LLM 本质上是无状态、概率性的语言预测引擎。CLI 参数提供了确定性的框架，限制 Agent 不越界、不幻觉，并按需继承特定上下文与算力资源。

解决什么根本问题？

解决“如何让 AI 代理既能自治完成复杂多步任务，又严格受控于人类的安全防线与工程标准”。

没有它时人们怎么办？

在 Web UI 中靠人类手动复制粘贴文件、在 Prompt 中一遍遍强调“请不要修改代码”、通过频繁的人工确认打破自动化链条。

带来了哪些新的可能？

允许将 Claude 深度集成进 CI/CD 自动化构建、Git 提交前置审查、无头（Headless）后台批量代码重构等高阶工程管线中。

AI 时代参数观：你不需要记住 40 个 flag 的具体拼写，你需要理解的是四大参数家族：上下文范围、能力授权、算力控制、协议交付。
02

世界模型：四大维度锁死 Agent 运行边界

参数不仅作用于终端命令行本身，更直接调控 API 认知模型、本地文件系统、MCP 工具网络与自动化管道。

1. 上下文控制
`--resume `恢复特定历史会话上下文与记忆
`--system-prompt`注入最高优先级的系统级行为准则
`--file `在启动时直接挂载特定文件上下文
2. 权限与安全
`--allowedTools`显式白名单授权 Agent 可执行的工具
`--dangerously-skip`绕过人工确认弹窗（仅限隔离容器）
`--mcp-config`连接外部 MCP 扩展服务工具集
3. 算力与模型
`--model `在 3.5 Sonnet / 3.7 Sonnet / Haiku 间切换
`--thinking-budget`分配深度推理 (Extended Thinking) Token 预算
`--max-tokens`硬性封顶单次响应的消耗与长度
4. 脚本与交付
`--print` / `-p`不进入 TTY 交互界面，直接打到 STDOUT
`--json`输出机器可读的结构化 JSON 响应
`--non-interactive`适合 CI 管道的无头只读运行模式
03

概念地图：解构 Claude CLI 参数家族

从实体、动作、目的与相互关系的视角，深刻理解各大参数族的本质设计意图。

Family 1 · 安全授权与工具防线

`--allowedTools` vs `--dangerously-skip-permissions`

Entity (名词): 工具访问权限白名单与安全断路器。

Action (动词): 预判与裁剪能力（`read_file`, `write_file`, `bash`），关闭交互式人工确认。

Purpose (目的): 在“全自动高效率”与“系统安全红线”之间建立精确可控的隔离带。

Relationship (关系): `--allowedTools` 是精细化最小权限原则 (PoLP) 的体现；`--dangerously-skip-permissions` 是在物理沙箱 (Docker) 内解除防线。

Family 2 · 认知开销与预算

`--thinking-budget` & `--model`

Entity (名词): 拓展思考 (Extended Thinking) Token 额度与模型档位。

Action (动词): 强制 Agent 在输出代码前开辟独立显式思维链 (Chain of Thought)。

Purpose (目的): 用更高的思考算力换取复杂重构任务的准确率，避免盲目写出低质量代码。

Relationship (关系): 简单修改使用低预算，复杂系统架构分析结合 Haiku/Sonnet 分配高 `thinking-budget`。

Family 3 · 自动化与管道输出

`--print` & `--json`

Entity (名词): 非交互式控制台输出流与机器可读协议。

Action (动词): 剥离终端 TTY 交互动画，将结构化 JSON 直接打入 STDOUT。

Purpose (目的): 允许 `claude` 被 Shell 管道 (`|`)、`jq` 或下游 Python 脚本消费。

Relationship (关系): 将 Claude 从一个人类使用的聊天软件，彻底转变为 Unix 工具链中的一个“高阶处理节点”。

04

决策地图：自动化场景下的参数组合策略

针对真实的工程应用场景，制定最稳妥的 Agent 参数契约方案。

Situation 场景：在 GitHub Actions CI 自动化构建管线中，让 Claude 自动审查 PR 代码并输出 JSON 审计报告。
↓
Decision 决策：使用组合参数 `claude -p "Review code" --non-interactive --allowedTools "read_file,git" --json`
↓
Reason 理由：剥离交互确认，仅授予只读工具权限以防修改代码仓库，且输出结构化 JSON 便于 CI 脚本解析结果。
↓
Expected Outcome 期望结果：安全、可预测、无阻塞地在 CI 中完成代码质量自动审查。
Situation 场景：面对遗留巨型代码库的重构，需要 AI 进行深入分析并设计长程重构方案。
↓
Decision 决策：使用 `claude --model claude-3-7-sonnet --thinking-budget 16000 --system-prompt "Architecture Expert"`
↓
Reason 理由：遗留代码分析极易陷入局部最优，给足 16k tokens 的 Extended Thinking 预算可让 Agent 在隐式思考中充分解构依赖关系。
↓
Expected Outcome 期望结果：获得具备大局观、全局无幻觉的深谋远虑重构方案。

超越基础 Flag 说明，探索影响 AI 智能体生产环境稳定性的核心问题。

07

可迁移原则：提取智能体配置的核心范式

标志性参数名未来可能会变，但对智能体授权与管理的架构范式永不过时。

第一性原理 (First Principles)

Boundary Control for Non-deterministic Systems: 对概率性 Agent 的治理，核心不在于指导它“如何一步步做”，而在于显式锁定它的“权限边界、输入依赖与输出契约”。

可迁移的方法论 (Transferable Methodologies)

最小权限与明确契约: 给 Agent 授权时始终遵守 PoLP 原则；在机器管道交互中始终要求 Structured Output (e.g. JSON)。

长期稳定的知识 (Stable Knowledge)

上下文窗口边界控制、人工确认与沙箱隔离屏障、Token 算力预算封顶、流式与结构化输出分离。

容易变化的知识 (Changing Knowledge)

具体模型名称字符串 (e.g. `claude-3-7-sonnet`)、具体参数命名的横杠写法、特定 API Key 的环境变量名称。

08

最小心智模型：智能体参数契约的 12 个关键概念

掌控这 12 个概念，即可自如配置任何现代 AI Agent 的 CLI 运行姿态。

  1. Agent Operating Contract (运行契约): 通过命令行选项显式约束 Agent 行为模式的配置文件或参数声明。
  2. Context Scope (上下文作用域): 决定 Agent 在启动瞬间继承哪些文件、历史对话或系统提示词。
  3. Tool Permission Whitelist (`--allowedTools`): 限制 Agent 仅能调用的特定安全原语集合。
  4. Safety Circuit Breaker (`--dangerously-skip`): 跳过交互确认的风险选项，必须配合隔离容器使用。
  5. Extended Thinking Budget (`--thinking-budget`): 显式分配给 Agent 进行深思熟虑思维链推导的算力额度。
  6. Model Tier Selection (`--model`): 根据任务复杂度在快省模型 (Haiku) 与深思模型 (Sonnet) 之间抉择。
  7. Session Persistence (`--resume` / `--session`): 跨命令保留与追溯 Agent 内存上下文的机制。
  8. Structured Machine Output (`--json`): 放弃渲染给人类眼睛看的格式，输出符合 Schema 的机器数据。
  9. Non-Interactive Mode (`-p` / `--print`): 解耦 TTY 终端，使得 Agent 运行在无头构建管道中。
  10. System Prompt Overrides (`--system-prompt`): 覆盖或追加 Agent 顶层元规矩的高优先配置。
  11. MCP Integration (`--mcp-config`): 给 Agent 插入外部数据库、GitHub 或内部系统的标准化工具扩展插槽。
  12. Hard Token Ceiling (`--max-tokens`): 兜底熔断机制，防止异常任务刷爆消费额度。
09

常见误区：打破对 Agent 参数的认知陷阱

避免因误解 CLI 选项而引发安全事故或低效使用。

误区一：`--dangerously-skip-permissions` 是一个无害的便捷开发参数

产生原因：讨厌频繁在终端点击 `y` 确认文件修改或 Bash 命令执行。

更准确的心智模型：该参数完全撤销了人类与系统之间的安全气囊。一旦 Agent 遭遇 Prompt 注入或产生幻觉，可能直接执行 `rm -rf /`；只有在轻量容器/沙箱中才允许开启。

误区二：挂载给 Agent 的上下文 (Files / Prompt) 越多越好

产生原因：认为大模型的上下文窗口巨大，一次性把整个项目代码挂载进去最省心。

更准确的心智模型：过多的无关上下文会导致注意力稀释 (Attention Dilution)、响应延迟陡增并极大地浪费 Prompt 缓存开销。精准提供相关模块才是专家做法。

误区三：Claude CLI 参数只用于控制终端显示格式

产生原因：用传统 `ls`, `grep` 的格式化 Flag 经验套用 AI CLI 工具。

更准确的心智模型：Agent CLI 参数直接决定了后端大模型的思考方式、本地操作系统的工具调用许可与自动化构建管线的接口契约。
