Learning map 02 · Claude CLI

参数不是开关清单，而是一次 Agent 运行的治理边界

理解 Claude 命令，最重要的不是背 flags，而是看清八个决策：它怎样工作、延续哪段记忆、使用什么能力、能动到哪里、如何被验证。

核心判断 Prompt 决定“想做什么”；参数决定“以什么运行形态、带什么上下文、在什么边界内做”。

01

本质：为 Agent 运行声明一个“任务容器”

Claude CLI 是终端中的 agentic runtime：模型负责推理，工具负责行动，权限系统限制行动，会话负责连续性，输出协议把结果交给人或其他机器。

它本质上不是聊天框，而是一个受上下文、能力和权限约束的 AI 执行环境。

为什么存在

代码与本机工作天然分布在文件、Git、终端、浏览器和外部服务中。Claude CLI 把自然语言意图接到这些可操作系统上，并维持多轮任务状态。

解决的根本问题

传统聊天只能建议“你可以怎么做”；Agent runtime 需要读取现场、选择工具、执行、观察失败、修复并验证。

过去怎么做

人把问题拆成命令、编辑器操作、网页查询和 Git 步骤，再手动串联。脚本能自动化已知路径，却难以处理开放式判断与异常。

新可能

同一个任务可以交互协作、非交互自动化、恢复旧会话、切换模型、隔离 worktree，并向流水线输出结构化结果。

最重要的分工：Prompt 是任务内容；CLI 参数是执行政策。前者常变，后者应该由风险、成本、可复现性和接收者决定。
02

世界模型：意图经过五道边界才成为副作用

Claude 不是直接“修改世界”；它在配置、模型、工具、权限和工作区共同定义的运行环境中行动。

Objects 对象
Prompt / System prompt任务意图与行为约束
Session对话、工具结果与连续状态
Workspace文件、Git、规则与当前目录
Tool resultAgent 观察现实的反馈
Actors 角色
用户目标、授权、验收和责任
Claude model推理、计划和选择工具
Runtime会话、配置、权限与工具调度
Tools / MCP / Plugins对本地与外部系统执行动作
State 状态
Context当前模型实际可见的信息
Permission允许、询问、拒绝或绕过
Filesystem / Git工作产物与版本状态
Output面向人、JSON 消费者或流式系统
构造运行环境目录、设置、Agent、模型和会话
理解意图Prompt 与规则形成当前任务模型
请求行动工具调用经过权限与范围判断
返回证据文本、JSON、流事件、diff 与测试产物
安全事实：--dangerously-skip-permissions 不是“更智能”或“更自动”，而是移除一道损害控制边界。只有外层沙箱已经可靠限制网络、文件与凭据时，才可能合理。
03

概念地图：三层、八个参数家族

先按“运行形态 → 治理边界 → 集成接口”理解，再记具体参数。

Layer 1
运行形态

交互 vs 非交互选择协作对话或一次性执行；关系到信任提示、输出协议和自动化。
会话连续性继续、恢复、复制或新建上下文；决定历史是否延续与分叉。
模型与 effort分配推理能力、速度和成本；决定任务的认知预算。

Layer 2
治理边界

权限模式决定工具调用何时自动、询问或禁止；控制副作用风险。
工具范围决定 Agent 能使用哪些行动通道；实现最小能力。
上下文与目录决定 Claude 看见哪些规则和文件；控制知识边界与作用域。

Layer 3
集成接口

结构化输入输出让其他程序可靠消费结果；把会话变成流水线节点。
扩展与诊断MCP、Plugin、Agent 和 debug 扩展能力或隔离故障。

① 交互方式

决定接收者是谁。默认交互会话面向人；print 模式面向管道、脚本和一次性任务。

claude [prompt]-p--print--background

② 会话身份

决定从哪段历史继续，以及是否分叉。“继续最近一次”和“恢复指定会话”不是同一语义。

-c / --continue-r / --resume [value]--fork-session--session-id--name

③ 认知预算

决定用什么模型、思考到什么深度、不可用时如何退路。能力、延迟和成本在这里交换。

--model--effort--fallback-model--max-budget-usd

④ 权限与工具

决定 Agent 能做什么、何时需要询问。--tools 定义可用集合；allow / disallow 进一步制定政策。

--permission-mode--tools--allowed-tools--disallowed-tools--dangerously-skip-permissions

⑤ 上下文与工作区

决定 Claude 从哪里开始、还能访问哪里、遵循哪些设置。工作目录既是上下文边界，也是风险边界。

--add-dir-w / --worktree--settings--setting-sources

⑥ 行为指令

决定是在默认行为上补充，还是整体替换。system prompt 是高权重行为层，不应拿来承载普通任务内容。

--append-system-prompt--system-prompt--agent--agents

⑦ 机器接口

决定数据如何进入和离开。文本面向人，JSON 面向单次机器消费，stream-json 面向实时事件系统。

--input-format--output-format--json-schema--include-partial-messages--no-session-persistence

⑧ 扩展与排障

决定加载哪些外部能力，或如何得到最小可诊断环境。排障先减少变量，再观察日志。

--mcp-config--strict-mcp-config--plugin-dir--debug--debug-file--safe-mode--bare

04

决策地图：先判断运行政策，再选参数

参数选择应该来自情境，而不是从帮助页随机挑功能。

Situation

你要与 Claude 共同澄清一个开放任务

Decision

使用默认交互会话

Reason

人需要在关键判断点补充上下文与验收

Outcome

目标逐步收敛，风险可见

Situation

结果要被脚本、CI 或另一 Agent 消费

Decision

--print + 合适的 --output-format，必要时加 schema

Reason

机器需要确定的结束条件和结构化协议

Outcome

Claude 成为可编排的流水线节点

Situation

要延续刚才工作，或恢复一段明确历史

Decision

最近会话用 --continue；指定会话用 --resume

Reason

连续性来自正确的 session，不来自“模型应该记得”

Outcome

减少重复读取，避免串错上下文

Situation

要探索新路线，但保留原会话轨迹

Decision

恢复时使用 --fork-session

Reason

分叉允许共享历史，同时隔离后续决策

Outcome

可比较方案，不污染原路线

Situation

任务涉及敏感目录或有限动作

Decision

限制目录、工具与 permission mode

Reason

最小权限能缩小误解意图时的损害面

Outcome

Agent 有足够能力，但没有无关能力

Situation

项目配置、Hooks 或 Plugin 让 Claude 异常

Decision

用 --safe-mode 隔离自定义项，再用 debug 获取证据

Reason

先减少变量，才能区分 runtime、配置与项目问题

Outcome

从“重装试试”转为可证伪诊断

05

搜索空间：重要问题不在参数名里

成熟使用者关心的是运行可重复性、上下文污染、权限闭环和失败恢复。

初学者很少问

  • Claude 当前真正加载了哪些规则、目录和 setting sources？
  • 恢复会话时，历史意图是否仍适用于今天的工作区状态？
  • 允许一个工具，是否同时放大了网络、凭据或文件风险？
  • 非交互模式为什么会改变 trust dialog 与错误呈现？

专家真正关心

  • 运行环境能否重建：模型、设置、工具、目录和版本是否明确？
  • 结构化输出契约在失败、部分流式消息和工具事件下是否仍稳定？
  • 工具授权是能力白名单，还是仅减少提示次数？
  • 长会话何时应压缩、交接、分叉或重新读取真实现场？

下一步值得探索

  • CLAUDE.md、system prompt、settings、Hooks、Skills 各处在哪个控制层？
  • MCP 与内置工具的信任边界有什么差别？
  • worktree 如何把 Git 路线与 Agent 会话隔离结合起来？
  • 如何为客户交付定义可审计、可回滚的 Agent policy？

定义掌握上限

  • 能否为不同风险等级设计不同的运行 profile？
  • 能否把一次优秀会话转成稳定的自动化契约，而非复制 prompt？
  • 能否证明 Agent 的权限不超过任务所需？
  • 能否在模型、工具或版本变化后检测行为漂移？
06

生态系统：Claude CLI 位于“意图层”和“执行层”之间

它既不是模型本身，也不是所有工具的替代品；它负责把推理、上下文、权限和行动组织成闭环。

上游 Upstream

人的目标与验收标准、项目规则、系统提示、模型能力、订阅或 API 供给。上游决定 Claude “知道什么、优先什么、承担多大认知预算”。

替代 Alternatives

Codex CLI、IDE 内 Agent、ChatGPT desktop、Claude desktop、直接 SDK、自建 Agent runtime。差异重点在现场访问、治理、扩展、可编排性和体验。

互补 Complements

Git / worktree 提供变更历史和路线隔离；测试与 CI 提供机器证据；MCP、Plugins、Skills 扩展能力；沙箱与权限策略限制损害面。

下游 Downstream

Shell、文件系统、浏览器、GitHub、云平台、数据库、消息系统和客户交付产物。Agent 价值必须在这些系统的真实状态中被验收。

07

可迁移原则：参数会变，治理逻辑不变

用稳定原则管理快速变化的模型名、flags 和扩展生态。

第一性原理

Agent 的实际能力 = 模型推理 × 可见上下文 × 可用工具 × 权限边界 × 反馈质量；任何一项为零，闭环都会断。

可迁移方法论

最小权限、上下文显式、会话可追踪、结构化接口、真实产物验收、故障先隔离变量、高风险动作外层沙箱。

稳定知识

交互 / 非交互、会话连续性、模型选择、工具能力、权限政策、输入输出协议、诊断与隔离。

实现细节

具体 flag 拼写、配置文件层级、permission mode 枚举、事件 JSON schema、Plugin 与 MCP 加载方式。

易变知识

模型别名、effort 等级、beta 选项、Chrome / Remote Control、background agents 与实验命令。使用前看当前 claude --help。

08

最小心智模型：只记住这 14 个概念

先记决策意义，再在需要时查询具体拼写。

  1. Runtime，不只是模型最终行为由模型、规则、工具、权限和现场共同产生。
  2. Prompt ≠ Policy任务内容放 prompt；运行边界由参数和配置治理。
  3. 交互 / Print前者面向协作，后者面向一次性执行与机器集成。
  4. Session identitycontinue、resume、fork 是三种不同的历史关系。
  5. Model + effort它们是能力、延迟和成本的预算选择。
  6. Permission mode决定行动何时允许、询问、拒绝或绕过。
  7. Tool scope可用、允许、禁止是能力集合与政策的组合。
  8. Working directory项目上下文和默认作用域从这里开始。
  9. Additional directories扩大可见范围也扩大潜在损害面。
  10. System promptappend 是补充，replace 是重建行为基线。
  11. Structured output机器消费需要 JSON、schema 或流事件，而不是“看起来清楚”。
  12. ExtensionsMCP、Plugin、Agent 带来能力，也带来新的信任边界。
  13. Safe mode / Debug排障的核心是隔离自定义变量并收集证据。
  14. Artifact verificationClaude 的最终回答不是完成证据；文件、diff、测试和外部状态才是。
09

常见误区：不要把“自动”误认为“受控”

参数最常见的误用来自对会话、权限和输出语义的混淆。

误解

--dangerously-skip-permissions 能让 Claude 更强。

为什么

少弹确认会让执行显得更流畅。

更好模型

它不增加推理能力，只移除保护边界；速度提升来自减少摩擦，风险同时扩大。

误解

--continue 总能找到“我想要的那次会话”。

为什么

“最近”容易被理解为全局最近。

更好模型

会话和当前目录 / 项目有关；需要指定历史时用 resume，并核对会话身份。

误解

换更强模型就能解决所有失败。

为什么

失败表面上像“模型没想明白”。

更好模型

很多失败来自上下文错误、工具缺失、权限拒绝、现场漂移或验收不清，模型只是系统的一环。

误解

--output-format json 意味着内容一定符合我的业务结构。

为什么

“JSON”被误当成了“正确 schema”。

更好模型

传输格式只保证外壳；业务字段约束需要 schema、验证和失败处理。

误解

加载更多 MCP、Plugin 和目录会让 Agent 更懂我。

为什么

能力数量看起来等于能力质量。

更好模型

过多能力会扩大搜索空间、上下文噪声和安全面；任务相关的最小工具集通常更可靠。

10

总结：真正的收益

重要参数是你与 Agent 之间的运行契约。

我真正获得的不是背会 Claude 的所有参数，而是为每次 Agent 运行设计清楚的上下文、能力、权限、成本与证据边界。
